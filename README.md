## 👋 About This Repository

This repository documents my journey from a Cybersecurity university student to a Product Security Engineer.

It is **not** simply a collection of tutorials or copied projects.

It is a public record of:

- What I learn
- What I build
- What I break in controlled environments
- What I secure
- What I research
- What I improve
- What I learn from failures
- How my engineering and security skills evolve over time

**The goal is to turn knowledge into real engineering ability through continuous hands-on practice.**

## 🛡️ Phase 02 — Application Security

**Duration:** Months 4–8

**Objective** — move from:

> *"I can build an application."*

to:

> *"I understand how the application works, how it can fail, how vulnerabilities arise, and how to prevent them."*

### Core Areas

`Web Architecture` `HTTP` `Authentication` `Authorization` `Sessions` `JWT` `OAuth2` `API Security` `Secure Cookies` `Security Headers` `CORS` `CSP` `CSRF` `Rate Limiting` `Secure File Uploads` `Secrets Management` `Secure Coding` `Code Review`

### OWASP Security Learning

For each vulnerability:

```
Understand
    ↓
Build a vulnerable application
    ↓
Test it in a controlled environment
    ↓
Understand the root cause
    ↓
Fix it
    ↓
Verify the fix
    ↓
Document the lesson
```

Areas include:
- Broken Access Control
- Cryptographic Failures
- Injection
- Insecure Design
- Security Misconfiguration
- Vulnerable Components
- Authentication Failures
- Software and Data Integrity Failures
- Logging and Monitoring Failures
- SSRF

> ⚠️ All testing is performed only against systems and environments where I have authorization.

### AppSec Tools

`Burp Suite` `OWASP ZAP` `Nuclei` `Semgrep` `Trivy` `Gitleaks` `Dependency Scanning tools`

### Major Project — 🔎 Mini AppSec Platform

- `sitemap.xml` analysis

## 🧪 Learning Philosophy

### 30% Theory — 70% Practice

I believe technical knowledge becomes valuable when it can be applied.

**My Learning Loop**

```
Learn → Understand → Build → Break → Secure → Test → Document → Share → Improve
```

**Core Principles**
- Learn by building.
- Every important technology should lead to practical work.
- Understand instead of memorizing.
- Document what I learn.
- Share useful knowledge.
- Continuously improve my portfolio.
- Compare myself with my previous progress, not with other people.
- Consistency beats intensity.
- Do not learn tools without understanding the underlying protocols and systems.
- Use AI as a tutor, reviewer and accelerator — not as a replacement for understanding.

---

## 🧠 AI Usage Philosophy

AI will be part of my development workflow, but the objective is to become an engineer who understands the system, not someone who simply generates code.

| AI Can Help Me | But I Should Be Able To |
|---|---|
| Explain concepts | Explain my own code |
| Debug errors | Debug important problems |
| Review code | Understand the architecture |
| Suggest improvements | Defend security decisions |
| Generate test cases | Rebuild important components |
| Analyze documentation | Explain why a vulnerability exists |
| Explore alternative implementations | Explain why a mitigation works |
| Help with research | |
